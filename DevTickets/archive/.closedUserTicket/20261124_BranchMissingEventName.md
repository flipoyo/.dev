The bootstrap of cawaqs's `.config/cawaqs-dev-4X.cgs` (cgitsync 8.11.1, HT-BETA 838ee24, 2026-11-24) logged `private_branch_missing` 18 times, once for each of the 17 libraries and `scripts`. None of them is private. They are project repositories (scope `project` in `cgitsync status`). The bootstrap did the right thing: it asked for `cawaqs_4X` (RootBareBranch), found that branch only on the private mounts' remotes, fell back on `main`, and logged the command that creates the branch. But the event name says "private", so a normal first-install fallback looked like a bug, and it took a ticket on the cawaqs side to work out that cgitsync was not at fault.

```
{"operation": "CGS-RUN", "event": "private_branch_missing", "repo": "libgc", "path": ".../src/libgc", "wanted": "cawaqs_4X", "landed": "main", "config": null, "command": "cgitsync branch create 4X && cgitsync checkout 4X", "project_branch": null}
```

- The event comes from `_assert_nested_discovery_complete` (`orchestre/client.py`, about line 1575). It records two cases under one name: `fell_back`, a writable private repository on a DEV tree, and `waits`, the root waiting on its fallback or a guest (`branches.guest(entry)`), which is how the libraries get in. The attribute it fills is `missing_private_branches`, which is misleading in the same way.
- Rename the event, and the attribute, to something that covers both cases, for example `branch_missing`, with a `scope` field (`private/local`, `project`, `guest`) so a reader sees which case fired. Or keep `private_branch_missing` for the private case only and log the other case under its own name. Whatever the choice, keep the old event name readable by anything that parses the run logs, or say in the changelog that it changed.
- Worth checking in the same change: the message tells a user tree "with info instead of a warning" (8.11.1). On a DEV tree, the first install of a new branch line falls back for every library, so 18 WARNING lines are expected. They could say "first install of this line: expected", as the bootstrap already says for the private mounts' fallback seed. It should be written explicitely at the end of the bootstrap that the user must run pixi run cgitsync branch create "project-name_branch" followed by checkout and push. One thing that is misterious to me is why it shouldn't be run for the private local repo. It should be the same for project parent 
- Not a bug, for the record: cgitsync 8.9.4, which cawaqs's pixi `dev` environment had locked until 2026-11-24, reports libraries on `cawaqs_<branch>` as "tree is split across branches … expected '4X'". 8.11.1 does not. No change is needed in ComplexGitSync for that.
